Selected work

RSO Zuid-Limburg · 2026

One query across a region's openEHR repositories

In Zuid-Limburg each care provider keeps patient data in its own openEHR repository, on purpose. An application that needed a patient's full record had to know every repository and query each one itself.

With RSO Zuid-Limburg and the openEHR SEC we drafted a specification for federating openEHR repositories, wrote an open reference implementation and built Unio on it. The SEC approved version 1.0.0 in October 2026.

A FHIR facade on an openEHR repository, built live

We ran the hands-on "Let's Build" session. Participants assembled an openEHR repository, Firely Server and openFHIR into one setup that returns stored data as a FHIR International Patient Summary and stores incoming FHIR data in openEHR.

Two products from our consulting work

Syntaric is a consultancy. We also build two products: openFHIR, which is open source under the Apache 2.0 licence and has a commercial Enterprise version, and Unio, which is commercial.

openFHIR

openFHIR maps data between openEHR and FHIR in both directions, so an openEHR repository can exchange data with FHIR systems. It implements FHIR Connect, an open specification for describing openEHR–FHIR mappings, which we co-created.

It was the bridge between openEHR and FHIR in the "Let's Build" session at HL7 Converge & Collaborate, Dublin 2026, and in our International Patient Summary webinar.

open-fhir.com

Unio

Unio makes several openEHR repositories answer as one. An application queries one openEHR endpoint and gets a patient's records from every member repository, while each record stays where it was created.

It implements the openEHR Federation Tier with AQL specification, version 1.0.0, approved by the openEHR SEC in October 2026.

unio.syntaric.com
